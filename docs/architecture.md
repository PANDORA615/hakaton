# Архитектура v0.1

Nginx отдаёт React и проксирует API/SSE в один FastAPI worker. PostgreSQL хранит исходные сущности, неизменяемые snapshots, версии настроек, результаты, пользователей и сессии.

Загрузка JSON проходит Pydantic-валидацию и проверку FK/уникальности, затем под блокировкой координатора в одной БД-транзакции заменяет исходные строки, создаёт версию snapshot и расчёт. Ошибка откатывает всё. Удаление выполняется от transactions к accounts, вставка в обратном порядке. Identity-последовательности PostgreSQL восстанавливаются после явных ID, включая пустые таблицы.

Проекции расчётов содержат immutable JSON. Они не ссылаются FK на изменяемый исходный слой: это сохраняет предыдущий опубликованный результат при замене источника. Последний committed calculation_run является опубликованной версией. Ответы содержат calculation_version, settings_version, source_version, as_of, time_mode.

SSE проверяет номер опубликованного расчёта и сессию раз в секунду. После новой версии frontend инвалидирует запросы. Сводка, таблица и открытая карточка имеют дополнительный интервал обновления 5 секунд; SSE также обновляет настройки/источники. Операции записи синхронные (HTTP 200 после завершения), достаточные для набора 10/30/100. При росте объёма переходить на задания с 202 и отдельный worker.

Время live пересчитывается каждые 60 секунд, fixed не движется. Пользовательские и таймерные изменения сериализованы process-local RLock: **не запускать больше одного worker**. Для масштабирования нужны очередь/распределённая координация, общие события и хранение индексируемых результатов вне одного JSON.

Ограничения исходной схемы сохранены: CHECK денег, статусов, периодов и performedAt, FK RESTRICT, индексы связей. PostgreSQL дополнительно получает regex имени и timestamptz(3). Приложение не исполняет исходный SQL seed при каждом запуске: это однократная загрузка для пустых fixture-таблиц.

## Проверка на PostgreSQL

В этой среде PostgreSQL не установлен. Подготовлена интеграционная проверка для **отдельной пустой тестовой БД**. Скрипт отказывается работать с URL без слова `test` в имени БД, с существующими таблицами приложения или с общей production-БД. Он создаёт таблицы только в выбранной тестовой БД, проверяет импорт и FK/последовательности, затем оставляет результат для инспекции.

В Compose-сети создайте отдельную БД, например retention_test, задайте `TEST_DATABASE_URL=postgresql+psycopg://.../retention_test` и из backend выполните `python scripts/check_postgres.py`. Фактически скрипт находится в корне проекта; при запуске контейнера смонтируйте его отдельно, либо запустите локальным Python из корня проекта после установки requirements.

Предпочтительная локальная команда из корня: `python scripts/check_postgres.py`. В окружении должна быть только тестовая строка подключения. Скрипт не принимает production DATABASE_URL как запасной вариант.

## История и последующие этапы

Snapshots и версии расчётов уже сохраняются. UI исторического оттока ещё не реализован: текущий deleted не содержит даты удаления. Для истории понадобятся наблюдения переходов с отдельным временем обнаружения и, по возможности, точным временем события источника. В v0.1 нет автоматической политики удаления старых snapshots/runs; до большой нагрузки нужна политика хранения.
