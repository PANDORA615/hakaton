# Демонстрация для жюри

1. Запустить Compose по README и войти. Показать оригинальные 10/30/100, фиксированное время и предупреждения о качестве.
2. Открыть Источники данных и добавить демосценарии. Получится 16/37/100; исходные записи сохранены.
3. В рейтинге выбрать высокий риск: demo-growth-studio@example.test. Показать ожидание оплаты, отключённое автопродление и недостаток средств.
4. Открыть demo-shared-balance@example.test: два платежа по 70 EUR и общий баланс 80 EUR дают дефицит 60 EUR. Баланс не учитывается дважды.
5. Открыть вторую вкладку. Изменить коэффициент модели, сохранить. Проверить новый номер расчёта, score, рейтинг и денежные показатели в обеих вкладках без reload.
6. Экспортировать snapshot, изменить balance демоклиента, импортировать и показать обновление. Для структурной ошибки показать отклонение без повреждения данных.
7. Проверить все четыре обязательные сортировки в обоих направлениях и карточку unknown с объяснением.
8. Открыть Swagger и metrics после входа. Сопоставить churn_loss_index_eur и уровни со сводкой.
9. Перезапустить backend и подтвердить сохранение коэффициентов.
10. Выйти, убедиться, что клиентские API и settings возвращают 401. Токен metrics не открывает клиентский API.

До защиты отдельно пройти Docker/PostgreSQL и браузерную проверку: в среде разработки они не подтверждены. Не выдавать синтетические сценарии за историю реальных пользователей или score за обученную вероятность.
