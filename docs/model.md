# Объяснимая модель v0.1

Score — индекс приоритета, не калиброванная вероятность. Используем правила, поскольку исходник не содержит размеченной истории оттока.

## Признаки услуги

| Код | Значение [0,1] | Вес |
| --- | --- | ---: |
| no_autoprolong | 1 при выключенном autoProlong и известном платеже в горизонте | 25 |
| funding_gap | Непокрытая часть обязательств / обязательства, либо 0 без обязательств | 30 |
| payment_wait | 1 для согласованного prolong_wait в окне пяти дней | 30 |
| expiry_urgency | max(0, 1 − max(дни до expiresAt, 0) / urgency_days) | 15 |

`score = 100 × Σ(вес × признак) / Σ весов`. Все веса >= 0, хотя бы один > 0. Уровни вычисляются до округления: low <30, medium <60, high >=60. Клиент получает максимум индексов продлеваемых услуг. Если хотя бы одна такая услуга не оценивается, итог клиента unknown; partial_score позволяет видеть известную часть. deleted и blocked исключаются из будущего продления.

В начальном строгом DTO все поля обязательны. При структурной неполноте импорт отклоняется, при семантическом противоречии статуса/дат услуга сохраняется с unknown. Поэтому coverage в этом адаптере равен 1 для оценённых услуг и 0 для исключённых. Порог coverage_threshold зарезервирован для адаптеров с частично доступными признаками и не меняет этот строгий контракт.

## Денежная оценка

Строим платежи на `[as_of, as_of + H]`, H=7 дней. hour/week — точные интервалы; month/quarter_year/half_year/year — календарные месяцы от исходной даты окончания, с ограничением последним днём месяца. Дата 31 января → 29 февраля → 31 марта в високосном году, без накопления сдвига.

Для prolong_wait учитываем один текущий неоплаченный платёж. Будущие платежи до восстановления не генерируем. Если просрочка превышает пять дней, не придумываем удаление или долг за сотни часов: исключаем прогноз и показываем проблему качества.

Доступно = balance + bonusBalance при bonusState=unlocked; withdrawBalance не используем. Расходуем общий доступный баланс последовательно по времени и ID услуги. Это сценарий покрытия, включая возможность ручной оплаты при autoProlong=false. Средства не дублируются.

```text
funding = unfunded / due (0 при due=0)
loss_index = due × (score/100) × (m + (1−m) × funding)
m = 0.5 по умолчанию
```

Пример: к оплате 100 EUR, дефицит 80 EUR, индекс 70 → 63 EUR. m настраивается. Дефицит усиливает и score, и денежный сценарий; это явное эвристическое допущение.

Суммируем по услугам, а не умножаем индекс клиента на все услуги. Неизвестные суммы не подменяем нулевым риском: итог подписывается частичным, рядом указано число исключённых услуг. Деньги — номинальные платежи, включая возможность покрытия бонусами; это не прогноз поступления новых реальных денег, не бухгалтерский убыток и не математическое ожидание.

Транзакции в исходнике генерируются независимо от price; из них нельзя восстановить текущий баланс, пополнения или надёжную историю непродлений. `not_performed` сам по себе не означает отказ платежа.

## Добавление признака

В v0.1 реестр и функции находятся в `app/features.py`: создайте функцию, возвращающую значение и объяснение, и добавьте Feature в FEATURES. Значения по умолчанию и метаданные панели формируются из реестра. При обновлении существующей установки потребуется миграция текущих весов для нового code с сохранением старых коэффициентов. Добавьте тест фактора и обновите описание модели. Основной агрегатор и маршруты API не меняются.
