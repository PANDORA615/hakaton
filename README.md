# Aéza Retention

Веб-приложение для анализа рисков непродления услуг: рейтинг клиентов, объяснимый score, денежная оценка, коэффициенты модели и качество данных.

**Версия beta 0.8.** Реализован сквозной вариант на FastAPI, PostgreSQL/SQLAlchemy и React/TypeScript. Интерфейс использует палитру Material 3 с оранжевым акцентом Aéza. Это проект хакатона, а не официальный кабинет провайдера.

Интерфейс по умолчанию следует светлой или тёмной теме операционной системы и реагирует на её изменение без перезагрузки. Кнопка темы в панели и на экране входа переключает режимы «Как в системе», «Светлая» и «Тёмная»; ручной выбор сохраняется в браузере. Цвета поверхностей и формы элементов основаны на Material 3 с оранжевым акцентом Aéza.

В beta 0.8 в меню профиля появился отдельный раздел «Настройки сайта»: тема, русский/английский интерфейс и валюта отображения RUB/USD/EUR. Выбор сохраняется в браузере. Исходные суммы и расчёт модели остаются в евро; валютный выбор меняет только показ сумм и ввод пробного сценария. Официальные курсы EUR и USD к рублю получаются из [XML Банка России](https://www.cbr.ru/development/SXML/) на сервере: проверка выполняется каждый час, успешная загрузка кэшируется на шесть часов. При недоступности источника показывается последний полученный курс (или резервный курс с датой 24.10.2026) с пометкой ожидания обновления и повторной попыткой через 15 минут.

В разделе «Клиенты» можно искать по email или ID, добавить клиента с автоматическим ID, номером телефона для обратной связи и начальным балансом и открыть карточку с заметным ID. Телефон сохраняется в реестре и доступен в карточке и очереди контактов. Добавление сохраняет новый снимок и пересчитывает аналитику. Импорт полного снимка в разделе источников заменяет реестр целиком, включая клиентов, добавленных вручную; перед импортом экспортируйте текущий снимок при необходимости.

Очередь контактов хранится в базе данных; заметки, статус, ответственный, дата следующего контакта, история разговоров и результат остаются после перезагрузки и перезапуска сервера. Просроченные контакты поднимаются в начало списка и доступны через фильтр «Напоминания». Выбранный фильтр списка сохраняется в браузере. «Что если?» пересчитывает модель на копии исходного снимка для выбранного баланса и автопродления, показывает индекс, уровень, баланс, сумму под риском и объяснение; результат не меняет сохранённые данные. Светлая тема использует тёплые поверхности и отчётливые рамки, а карточка индекса следует выбранной теме.

Помощник знакомит с основными разделами после первого входа. При наведении или нажатии на лисёнка открывается меню: «Спросить у лисёнка» ищет ответ в справочнике проекта и предлагает переход, «Навигация по сайту» запускает пошаговый маршрут. Помощника можно выключить в «Настройках сайта»; выбор и факт прохождения сохраняются в браузере. В меню профиля есть отдельный «Справочник» по всем разделам и действиям. Поиск в центре верхней панели находит разделы и клиентов по email/ID; на узких экранах он открывается кнопкой с лупой. Поиск клиентов использует уже защищённый API и не показывает данные до авторизации.

После успешного парольного или OIDC-входа показывается короткое приветствие с именем пользователя. Карточки показателей на обзоре доступны мышью, клавиатурой и касанием: денежные показатели открывают график прогноза, клиентские — реестр. Для телефонов и планшетов адаптированы меню лисёнка, форма вопроса, таблица конкурентного радара и приветствие.

Форма входа показывается сразу после загрузки интерфейса; проверка уже существующей сессии идёт в фоне. Вход по паролю остаётся доступным. Когда OIDC настроен, кнопка «Войти через единый вход» перенаправляет к провайдеру и возвращает пользователя после проверки токена. Если провайдер не настроен, доступен отдельный экран демонстрации этого сценария.

На форме входа есть «Запомнить меня». Без отметки сеанс действует только до новой загрузки страницы: при обновлении или повторном открытии сайта интерфейс завершает его и возвращает форму входа. С отметкой сеанс восстанавливается до 30 дней либо до явного выхода или отзыва сеансов. Пароль в браузере не сохраняется. Выбор также передаётся через реальный OIDC-вход и демонстрационный экран.

### Настройка OIDC

Для включения единого входа нужны HTTPS-адрес приложения и данные вашего OIDC-провайдера. Заполните все переменные `OIDC_*` в `.env`:

| Переменная | Значение |
| --- | --- |
| `OIDC_ISSUER_URL` | HTTPS issuer провайдера с доступным discovery endpoint |
| `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | Учётные данные конфиденциального клиента |
| `OIDC_CALLBACK_URL` | Публичный HTTPS URL вида `https://ваш-домен/api/v1/auth/oidc/callback`; зарегистрируйте его у провайдера без изменений |
| `OIDC_ALLOWED_SUB` | Точный `sub` одной разрешённой учётной записи; несколько значений отклоняются, пока нет отдельных аккаунтов сотрудников |
| `OIDC_SESSION_SECRET` | Случайная строка длиной от 32 символов для временной cookie OIDC |

Интеграция использует Authorization Code с PKCE S256, `state` и `nonce`. Подписанный ID-токен проверяется по ключам провайдера, issuer, audience, сроку действия и nonce; приложение дополнительно требует точного совпадения `sub` с `OIDC_ALLOWED_SUB`. Лишь после этого создаётся локальная сессия. Пока параметры не заданы, кнопка OIDC скрыта. Не используйте email или имя пользователя вместо `sub`: они могут измениться.

Сейчас в приложении один локальный администратор, поэтому разрешён ровно один OIDC subject. Для подключения корпоративного провайдера зарегистрируйте конфиденциальный web-клиент с указанным HTTPS callback, включите Authorization Code и PKCE S256, задайте секреты вне Git и проверьте вход, отказ в доступе и выход в отдельном браузере. Если нужны несколько сотрудников, сначала добавьте отдельные локальные аккаунты и явную привязку каждого `(issuer, sub)` к своему аккаунту; общий администраторский доступ через список `sub` намеренно запрещён.

Для демонстрационного сервера дополнительно есть `compose.oidc.yaml`: Dex с локальной учётной записью и Caddy с HTTPS. Запуск: `docker compose --env-file .runtime/stack.env -f compose.yaml -f compose.oidc.yaml up -d --build`. Приватные настройки в `.runtime/stack.env` и `.runtime/oidc.env` исключены из Git. Демо-пароль находится в `.runtime/oidc-credentials.txt`. Старый адрес на порту 8080 перенаправляет на HTTPS. Пароль Dex относится к отдельной учётной записи провайдера; изменение локального пароля администратора в настройках аккаунта его не меняет.

Для репетиции без внешнего провайдера см. [тестовый OIDC-сценарий](docs/hackathon-oidc.md). Он включает изолированную проверку протокола и показ через встроенный Dex.

## Быстрый запуск на Windows

Нужен Docker Desktop с Linux containers и работающим Docker Compose. Распакуйте проект и откройте PowerShell в папке, содержащей `compose.yaml`.

1. Создайте настройки и случайные пароли:

   ```powershell
   py scripts/init_env.py
   ```

   Нужен Python 3.10+ только для этой вспомогательной команды. Если Python нет: скопируйте `.env.example` в `.env`, откройте `.env` в редакторе и заполните `POSTGRES_PASSWORD`, `ADMIN_PASSWORD`, `METRICS_TOKEN`. Для пароля БД используйте латинские буквы и цифры; пароль администратора — минимум 12 символов. Логин — `admin`.

2. Запустите:

   ```powershell
   docker compose up --build -d
   docker compose ps
   ```

3. Дождитесь healthy для сервисов и откройте **http://localhost:8080**. Войдите с паролем, выведенным init_env.py либо заданным вами в `.env`.

4. Исходный `data/original/data.json` импортируется автоматически только при первом запуске пустой БД. Панель покажет 10 аккаунтов, 30 услуг и 100 транзакций. Это данные, а не числа, зашитые в показатели.

В Compose три сервиса: PostgreSQL, backend и frontend/Nginx. БД и backend не публикуют порты на хосте. Панель по умолчанию привязана к `127.0.0.1`. Для доступа с другого устройства задайте `APP_BIND=0.0.0.0`, обеспечьте HTTPS и установите `COOKIE_SECURE=true` при HTTPS. Не выставляйте приложение в интернет с паролями для демонстрации.

Пароль администратора создаётся только при первом запуске. Изменение `ADMIN_PASSWORD` в окружении не перезаписывает пароль уже существующего пользователя. Текущая версия не содержит UI управления пользователями; используйте отдельную БД для новой демонстрационной установки.

## Что проверить в панели

1. **Обзор рисков:** распределение клиентов, сценарная сумма платежей под риском, дефицит средств и календарь известных продлений.
2. **Клиенты:** сортировки ID, email, баланса, общей суммы пополнений и score в обе стороны; поиск, фильтр риска, пагинация.
3. Нажмите клиента: откроются услуги, балансы, факторы и их вклады, денежная оценка и предупреждения.
4. **Источники данных → Добавить демосценарии:** добавляет 6 явно помеченных клиентов и 7 услуг к текущим данным. На оригинале получается 16 клиентов, 37 услуг, 100 транзакций. Исходные записи не изменяются.
5. **Модель риска:** измените вес и сохраните. Пересчёт синхронный для небольшого набора; сохранение и публикация новой версии атомарны. Открытые вкладки получают SSE-событие и обновляют результаты; таблица и summary дополнительно опрашиваются раз в 5 секунд.
6. **Источники данных:** экспортируйте snapshot, измените баланс одного демоклиента, загрузите JSON. Перед полной заменой интерфейс просит подтверждение. Некорректный импорт не повреждает текущие данные.
7. **Загрузить оригинал** возвращает исходный набор, сохраняя настройки модели. Это полная замена текущего источника; при необходимости сначала экспортируйте его.

### Работа с риском

- На обзоре график по дням разделяет известные платежи и сценарную сумму под риском. История статусов показывает наблюдавшиеся переходы между загруженными снимками. «Удаление» считается фактом только при переходе услуги в `deleted`; исчезновение записи без такого статуса не трактуется как отток.
- На «Обзоре рисков» кнопки «К графику» и «Что если?» ведут прямо к прогнозу и сценарию для клиента с наибольшим score. В карточке клиента блок «Что если?» пересчитывает оценку при другом основном балансе и/или автопродлении выбранной услуги. Проба не сохраняет снимок и не меняет показатели остальных пользователей.
- Кнопка «Добавить в работу» создаёт запись в очереди маркетолога. На вкладке «Работа с клиентами» можно назначить ответственного, запланировать следующий контакт, посмотреть напоминания, записать каждый разговор с каналом связи, фиксировать статус, заметку и фактический итог продления. Изменения защищены версией записи: при конфликте черновик остаётся в форме. Отдельный экран «Результаты» показывает отмеченные продления, отказы и долю продлений среди известных итогов. Это наблюдаемые итоги, а не доказательство эффекта контакта. Записи сохраняются после перезапуска и остаются видимыми, даже если клиент исчез из нового снимка.
- Горизонт анализа можно быстро переключить на 1, 7, 14 или 30 дней в шапке страницы. Выбор сохраняется в настройках модели и пересчитывает аналитику; произвольное значение от 1 до 30 дней доступно в модели.
- Меню аватара справа вверху открывается при наведении, фокусе или нажатии и содержит настройки аккаунта, модель риска и выход.
- Пробный сценарий «Что если?» привязан к входным параметрам и версии расчёта. При изменении параметров или исходного расчёта старое сравнение помечается устаревшим до повторного запуска.
- Режим темы по умолчанию следует настройке ОС. Ручной выбор сохраняется в браузере; переходы цветов и индикатора вкладки анимированы, если в ОС не включено уменьшение движения.
- Левая панель прокручивается колёсиком независимо от основного содержимого, если её пункты не помещаются по высоте.
- Фильтр уровня риска в разделе «Клиенты» использует цветовые метки и фон каждого уровня, соответствующий выбранной теме.
- Раздел «Аккаунт» позволяет изменить отображаемое имя, логин и контактный email, посмотреть сведения о входе и сеансах, сменить пароль и завершить остальные сеансы. Для смены логина нужен текущий пароль; смена пароля автоматически отзывает другие сеансы.

### Время и качество исходного набора

Compose по умолчанию использует явно обозначенное фиксированное время `2026-10-19T15:00:00Z` из генератора. В панели оно показывается как 19 октября, 18:00 МСК. Время не сдвигается скрытно.

У оригинала 8 противоречий: шесть prolong_wait за пределами пятидневного окна и две просроченные suspended. Такие услуги сохраняются, но не получают прогноз: `score=null`, причина качества данных, частичная денежная сумма. Аккаунт без продлеваемых услуг тоже имеет «Нет оценки». На исходных настройках и опорной дате: low=2, medium=1, high=0, unknown=7. Это контроль результата для конкретного набора, а не предустановленные показатели UI.

Демосценарии согласуются с текущим `as_of`. После добавления к оригиналу на начальных настройках присутствуют все четыре уровня (3/3/3/7 для low/medium/high/unknown).

Время задаёт `ANALYSIS_AS_OF`: отсутствие переменной включает демонстрационное фиксированное `2026-10-19T15:00:00Z`, дата с часовым поясом включает fixed, пустое значение включает live UTC. Некорректная дата останавливает запуск с понятной ошибкой. В live расчёт обновляется при импорте, изменении модели и каждые 60 секунд. Для live-режима источник должен поставлять актуальные snapshots; исходный октябрьский набор со временем устаревает. В исходнике нет истории смены статусов и дат удаления: исторический отток не выдумываем.

История хранится в пределах `RETENTION_RUN_LIMIT=200` расчётов и `RETENTION_SNAPSHOT_LIMIT=100` видимых снимков по умолчанию. Предшествующий снимок для первого перехода и версии, на которые ссылаются оставшиеся расчёты, сохраняются дополнительно. Очистка идёт порциями по 100 записей после публикации; её ошибка не откатывает текущий расчёт.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/v1/auth/login` | Вход: `{login, password, remember_me?}` |
| GET | `/api/v1/auth/me` | Пользователь и CSRF-токен |
| GET/PUT | `/api/v1/account[/profile]` | Профиль пользователя и его изменение |
| POST | `/api/v1/account/password` | Смена пароля и отзыв других сеансов |
| POST | `/api/v1/account/sessions/revoke` | Завершение других сеансов |
| GET | `/api/v1/auth/methods` | Доступные способы входа |
| GET | `/api/v1/auth/oidc/start` | Начало единого входа при настройке OIDC |
| GET | `/api/v1/auth/oidc/callback` | Возврат от OIDC-провайдера |
| POST | `/api/v1/auth/logout` | Отзыв сессии |
| GET | `/api/v1/customers` | Рейтинг, сортировки, фильтры, пагинация |
| GET | `/api/v1/customers/{customer_id}` | Подробная карточка |
| GET | `/api/v1/analytics/summary` | Агрегаты, версии, качество, календарь |
| GET | `/api/v1/analytics/history` | История наблюдавшихся переходов статусов |
| POST | `/api/v1/customers/{customer_id}/simulate` | Несохраняемый сценарный расчёт |
| GET/PUT | `/api/v1/actions[/{customer_id}]` | Очередь контактов; PUT изменения передаёт `expected_version`, конфликт даёт 409 с актуальной записью |
| POST | `/api/v1/actions/{customer_id}/contacts` | Запись разговора в историю; `expected_version` защищает от конфликтов, запрос требует CSRF |
| GET | `/api/v1/actions/outcomes` | Сводка и журнал отмеченных результатов продления |
| GET/PATCH | `/api/v1/model/settings` | Конфигурация модели |
| PUT | `/api/v1/source/snapshot` | Полная атомарная замена источника |
| GET | `/api/v1/source/snapshot` | Экспорт текущего источника |
| POST | `/api/v1/source/demo` | Дополнительные демосценарии |
| POST | `/api/v1/source/original` | Возврат к исходному набору |
| GET | `/api/v1/events` | SSE о новой версии расчёта |
| GET | `/metrics` | Prometheus |
| GET | `/api/v1/docs` | Swagger после входа |
| GET | `/api/v1/openapi.json` | Защищённая спецификация |

JSON-спецификация приложена в `docs/api/openapi.json`. Swagger JS/CSS поставляются внутри Python-зависимости, внешний CDN для документации не требуется.

API использует HttpOnly/SameSite cookie. После login/me передавайте возвращённый `csrf_token` в заголовке `X-CSRF-Token` для PATCH/PUT/POST, кроме login. Токен сессии хранится в БД в виде SHA-256, пароли — Argon2id. Сессия действует 8 часов; logout прекращает SSE после следующей проверки сессии. Есть ограничение попыток входа. Вход ограничен same-origin.

PATCH принимает `expected_settings_version` для защиты от одновременного редактирования. При конфликте возвращает 409, при неверных настройках — 422. PATCH и PUT возвращают **200, status=completed** только после успешного сохранения и пересчёта. Это осознанное упрощение раннего плана с очередью/202 для небольшого набора.

Параметры рейтинга: `sort_by=id|email|balance|totalReplenished|score`, `sort_order=asc|desc`, `risk_level`, `search`, `page`, `page_size`. Сортировка выполняется до пагинации; неизвестный score всегда в конце. Данные сортируются в памяти опубликованного расчёта: для большого production-набора понадобится индексируемая проекция в БД.

## Prometheus

`/metrics` доступен с сессией или отдельным `METRICS_TOKEN`. Токен сборщика не даёт доступ к клиентским API.

Пример scrape-конфигурации, если Prometheus в той же Docker-сети:

```yaml
scrape_configs:
  - job_name: retention
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials_file: /run/secrets/retention_metrics_token
    static_configs:
      - targets: [backend:8000]
```

Поместите значение токена в указанный файл сборщика. Сам Prometheus в Compose не включён. Проверка с хоста после задания токена в окружении PowerShell:

```powershell
Invoke-WebRequest http://localhost:8080/metrics -Headers @{ Authorization = "Bearer $env:METRICS_TOKEN" }
```

Есть количества всех уровней, сценарная сумма EUR, известные обязательства, дефицит, неизвестные услуги, средний индекс известных клиентов, версия и время расчёта. Если оценённых клиентов нет, средний score — NaN, число оценённых — 0. Персональные данные не используются в метках.

## Модель, архитектура и расширение

Смотрите `docs/model.md`, `docs/architecture.md`, `docs/demo.md`. Стартовые веса: выключенное автопродление 25, дефицит 30, ожидание оплаты 30, срочность 15. Средний риск от 30, высокий от 60. Score не является обученной вероятностью оттока.

Деньги исходника хранятся в евроцентах; 100 единиц = 1 EUR. Доступный баланс — основной плюс бонусы только при unlocked, без withdrawBalance. Баланс распределяется между услугами один раз по времени платежа и ID. Периоды оплаты рассчитываются календарно; суммы транзакций не заменяют цену услуги.

Интерфейс показывает суммы в рублях по фиксированному курсу Банка России на 24.10.2026: 1 EUR = 90,2429 RUB. Это демонстрационный пересчёт, а не текущий обменный курс. Поле баланса в сценарии «Что если?» принимает рубли и переводит их обратно в евроценты для расчёта. Исходные данные, API и технические метрики сохраняют исходные единицы EUR/евроценты; поэтому рублёвые значения интерфейса не следует напрямую сравнивать с полями API `_eur`.

## Проверки и ограничения

В среде разработки проверены:

- backend: 65 pytest-проверок на SQLite, включая денежный пример 63 EUR, общий баланс/бонусы, календарь, реальные DTO, сортировки, сессии/CSRF, запоминание входа, профиль и безопасность аккаунта, повторный импорт, сценарии «Что если?», историю статусов, конкурентные контакты, режимы времени, ограничение истории, OIDC-маршруты и изолированный тест подписанного ID-токена, рестарт, метрики и SSE;
- оригинальный генератор: 3 unittest-проверки, совпадение JSON и SQL;
- production-сборка React/TypeScript;
- генерация OpenAPI и компиляция схемы для PostgreSQL.

На сервере проверены сборки Docker, миграция PostgreSQL, запуск Compose и ответы основных API. Перед защитой проверьте пользовательский сценарий в браузере с актуальными данными.

Ограничения прототипа: один backend worker; расчёты и опубликованный JSON рассчитаны на небольшой набор; нет ML и управления несколькими пользователями. Демонстрационный Dex работает с HTTPS на сервере и имеет отдельный пароль, который не меняется через настройки локального аккаунта. При падении периодического расчёта остаётся предыдущая опубликованная версия, а число ошибок доступно в summary/metrics. Внешний веб-шрифт необязателен: при недоступности используется системный.

Порядок обновления, резервного копирования и восстановления описан в [docs/deploy.md](docs/deploy.md).

### Тесты через Compose

После сборки:

```bash
docker compose run --rm backend python -m pytest -q
docker compose run --rm backend python -m unittest discover -s /app/data/original -p test_generate.py -v
```

API-тесты используют отдельные временные SQLite-БД, не рабочую БД приложения. Для PostgreSQL-интеграции есть `scripts/check_postgres.py`; запускайте только против отдельной пустой тестовой БД (см. docs/architecture.md).

### Локальная разработка без Docker

Python 3.12, Node.js 22+ и npm. SQLite используется только для локального запуска и тестов; Compose использует PostgreSQL.

```bash
python -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cd frontend
npm ci
cd ..
python scripts/init_env.py
npm run dev
```

На Windows вместо `.venv/bin/python` используйте `.venv\Scripts\python.exe`, а вместо `python` при необходимости `py`. `scripts/dev.mjs` запускает миграции, backend на 8000 и Vite на 4173. Откройте http://localhost:4173 . В `.env` для локальной SQLite не задавайте DATABASE_URL; launcher создаст `.runtime/aeza.db`.

Сборка frontend: `cd frontend && npm run build`. Тесты backend: из `backend` запустите `../.venv/bin/python -m pytest -q` (на Windows путь к python.exe соответственно).

## Остановка

```bash
docker compose stop
docker compose start
```

Настройки, пользователи и данные находятся в volume PostgreSQL. Обычная остановка не удаляет volume. Файл `001_schema.down.sql` разрушителен и не используется приложением при запуске или остановке.

### Конкурентный радар

Радар получает тарифы напрямую с официальных страниц [Aéza](https://aeza.ru/virtual-servers), [FirstVDS](https://firstvds.ru/docs/tariffs.html) и [RUVDS](https://ruvds.com/ru/vps_start/). Сервер проверяет каждый источник не реже одного раза в 72 часа. Снимки сохраняются в PostgreSQL; при недоступности сайта остаётся последняя успешная версия с заметной отметкой о её возрасте. Неуспешные источники повторно проверяются через час. Клиент запрашивает сохранённый каталог раз в час. Сравнение основано на опубликованных месячных ценах, vCPU, RAM и объёме диска. Скидки на длительную предоплату и свойства без данных обеих сторон в выводах не учитываются. Перед покупкой проверяйте тариф и условия на странице провайдера.

Для Aéza в сборку включён проверенный 24.10.2026 первоначальный снимок: он используется лишь если первый запрос к сайту не удался, помечается ошибкой источника и автоматически заменяется после успешной проверки. Через 72 часа такой снимок также считается устаревшим.

Радар дополнен фиксированными VPS/VDS-линейками [Selectel](https://selectel.ru/services/cloud/vps-vds/daily-paid/), [AdminVPS](https://adminvps.ru/vps/vps_linux.php) и [Beget](https://beget.com/ru/vps). У Selectel опубликована цена за день: для сопоставления показана стоимость 30 дней, а дневная ставка сохранена рядом. У Beget месячная цена VPS показывается отдельно от опубликованной доплаты за публичный IPv4; переключатель позволяет включить её в сравнение. Индивидуальные конфигурации и скидки за длительную предоплату не включены. Вопросы клиента в радаре — сценарии уточнения потребностей, а не обобщения отзывов; вывод опирается на опубликованную цену и ресурсы.

Selectel иногда не отвечает на серверный HTTPS-запрос. В этом случае радар показывает датированный снимок с официальной страницы, проверенный 25.10.2026 в 00:07 UTC, явно отмечает сбой источника и повторяет запрос каждый час до успешной замены. После успешного обновления обычный интервал снова составляет 72 часа. Предполагаемые жалобы конкурентов не публикуются как факты: сценарий удержания задаёт вопросы клиенту и ссылается на проверяемые условия тарифов.
