# Aéza Retention

Веб-приложение для анализа рисков непродления услуг: рейтинг клиентов, объяснимый score, денежная оценка, коэффициенты модели и качество данных.

**Версия 0.4.** Реализован сквозной вариант на FastAPI, PostgreSQL/SQLAlchemy и React/TypeScript. Интерфейс использует палитру Material 3 с оранжевым акцентом Aéza. Это проект хакатона, а не официальный кабинет провайдера.

Интерфейс по умолчанию следует светлой или тёмной теме операционной системы и реагирует на её изменение без перезагрузки. Кнопка темы в панели и на экране входа переключает режимы «Как в системе», «Светлая» и «Тёмная»; ручной выбор сохраняется в браузере. Цвета поверхностей и формы элементов основаны на Material 3 с оранжевым акцентом Aéza.

## Быстрый запуск на Windows

Нужен Docker Desktop с Linux containers и работающим Docker Compose. Распакуйте проект и откройте PowerShell в папке, содержащей `compose.yaml`.

1. Создайте настройки и случайные пароли:

   ```powershell
   py scripts/init_env.py
   ```

   Нужен Python 3.10+ только для этой вспомогательной команды. Если Python нет: скопируйте `.env.example` в `.env`, откройте `.env` в редакторе и заполните `POSTGRES_PASSWORD`, `ADMIN_PASSWORD`, `METRICS_TOKEN`. Для пароля БД используйте латинские буквы и цифры; пароль администратора — минимум 12 символов. Логин — `admin`.

2. Запустите:

   ```powershell
   docker compose up --build -d
   docker compose ps
   ```

3. Дождитесь healthy для сервисов и откройте **http://localhost:8080**. Войдите с паролем, выведенным init_env.py либо заданным вами в `.env`.

4. Исходный `data/original/data.json` импортируется автоматически только при первом запуске пустой БД. Панель покажет 10 аккаунтов, 30 услуг и 100 транзакций. Это данные, а не числа, зашитые в показатели.

В Compose три сервиса: PostgreSQL, backend и frontend/Nginx. БД и backend не публикуют порты на хосте. Панель по умолчанию привязана к `127.0.0.1`. Для доступа с другого устройства задайте `APP_BIND=0.0.0.0`, обеспечьте HTTPS и установите `COOKIE_SECURE=true` при HTTPS. Не выставляйте приложение в интернет с паролями для демонстрации.

Пароль администратора создаётся только при первом запуске. Изменение `ADMIN_PASSWORD` в окружении не перезаписывает пароль уже существующего пользователя. Текущая версия не содержит UI управления пользователями; используйте отдельную БД для новой демонстрационной установки.

## Что проверить в панели

1. **Обзор рисков:** распределение клиентов, сценарная сумма платежей под риском, дефицит средств и календарь известных продлений.
2. **Клиенты:** сортировки ID, email, баланса, общей суммы пополнений и score в обе стороны; поиск, фильтр риска, пагинация.
3. Нажмите клиента: откроются услуги, балансы, факторы и их вклады, денежная оценка и предупреждения.
4. **Источники данных → Добавить демосценарии:** добавляет 6 явно помеченных клиентов и 7 услуг к текущим данным. На оригинале получается 16 клиентов, 37 услуг, 100 транзакций. Исходные записи не изменяются.
5. **Модель риска:** измените вес и сохраните. Пересчёт синхронный для небольшого набора; сохранение и публикация новой версии атомарны. Открытые вкладки получают SSE-событие и обновляют результаты; таблица и summary дополнительно опрашиваются раз в 5 секунд.
6. **Источники данных:** экспортируйте snapshot, измените баланс одного демоклиента, загрузите JSON. Перед полной заменой интерфейс просит подтверждение. Некорректный импорт не повреждает текущие данные.
7. **Загрузить оригинал** возвращает исходный набор, сохраняя настройки модели. Это полная замена текущего источника; при необходимости сначала экспортируйте его.

### Работа с риском

- На обзоре график по дням разделяет известные платежи и сценарную сумму под риском. История статусов показывает наблюдавшиеся переходы между загруженными снимками. «Удаление» считается фактом только при переходе услуги в `deleted`; исчезновение записи без такого статуса не трактуется как отток.
- На «Обзоре рисков» кнопки «К графику» и «Что если?» ведут прямо к прогнозу и сценарию для клиента с наибольшим score. В карточке клиента блок «Что если?» пересчитывает оценку при другом основном балансе и/или автопродлении выбранной услуги. Проба не сохраняет снимок и не меняет показатели остальных пользователей.
- Кнопка «Добавить в работу» создаёт запись в очереди маркетолога. На вкладке «Работа с клиентами» можно фиксировать статус контакта и заметку. Записи сохраняются после перезапуска и остаются видимыми, даже если клиент исчез из нового снимка.
- Режим темы по умолчанию следует настройке ОС. Ручной выбор сохраняется в браузере; переходы цветов и индикатора вкладки анимированы, если в ОС не включено уменьшение движения.
- Левая панель прокручивается колёсиком независимо от основного содержимого, если её пункты не помещаются по высоте.

### Время и качество исходного набора

Compose по умолчанию использует явно обозначенное фиксированное время `2026-10-19T15:00:00Z` из генератора. В панели оно показывается как 19 октября, 18:00 МСК. Время не сдвигается скрытно.

У оригинала 8 противоречий: шесть prolong_wait за пределами пятидневного окна и две просроченные suspended. Такие услуги сохраняются, но не получают прогноз: `score=null`, причина качества данных, частичная денежная сумма. Аккаунт без продлеваемых услуг тоже имеет «Нет оценки». На исходных настройках и опорной дате: low=2, medium=1, high=0, unknown=7. Это контроль результата для конкретного набора, а не предустановленные показатели UI.

Демосценарии согласуются с текущим `as_of`. После добавления к оригиналу на начальных настройках присутствуют все четыре уровня (3/3/3/7 для low/medium/high/unknown).

Для рабочего времени задайте `ANALYSIS_AS_OF=` в `.env` и пересоздайте backend: `docker compose up -d backend`. Пересчёт выполняется при импорте, настройках и каждые 60 секунд. У статичного примера будут появляться новые противоречия сроков; для live-режима источник должен поставлять актуальные snapshots. В исходнике нет истории смены статусов и дат удаления: исторический отток не выдумываем.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/v1/auth/login` | Вход: `{login, password}` |
| GET | `/api/v1/auth/me` | Пользователь и CSRF-токен |
| POST | `/api/v1/auth/logout` | Отзыв сессии |
| GET | `/api/v1/customers` | Рейтинг, сортировки, фильтры, пагинация |
| GET | `/api/v1/customers/{customer_id}` | Подробная карточка |
| GET | `/api/v1/analytics/summary` | Агрегаты, версии, качество, календарь |
| GET | `/api/v1/analytics/history` | История наблюдавшихся переходов статусов |
| POST | `/api/v1/customers/{customer_id}/simulate` | Несохраняемый сценарный расчёт |
| GET/PUT | `/api/v1/actions[/{customer_id}]` | Очередь контактов маркетолога |
| GET/PATCH | `/api/v1/model/settings` | Конфигурация модели |
| PUT | `/api/v1/source/snapshot` | Полная атомарная замена источника |
| GET | `/api/v1/source/snapshot` | Экспорт текущего источника |
| POST | `/api/v1/source/demo` | Дополнительные демосценарии |
| POST | `/api/v1/source/original` | Возврат к исходному набору |
| GET | `/api/v1/events` | SSE о новой версии расчёта |
| GET | `/metrics` | Prometheus |
| GET | `/api/v1/docs` | Swagger после входа |
| GET | `/api/v1/openapi.json` | Защищённая спецификация |

JSON-спецификация приложена в `docs/api/openapi.json`. Swagger JS/CSS поставляются внутри Python-зависимости, внешний CDN для документации не требуется.

API использует HttpOnly/SameSite cookie. После login/me передавайте возвращённый `csrf_token` в заголовке `X-CSRF-Token` для PATCH/PUT/POST, кроме login. Токен сессии хранится в БД в виде SHA-256, пароли — Argon2id. Сессия действует 8 часов; logout прекращает SSE после следующей проверки сессии. Есть ограничение попыток входа. Вход ограничен same-origin.

PATCH принимает `expected_settings_version` для защиты от одновременного редактирования. При конфликте возвращает 409, при неверных настройках — 422. PATCH и PUT возвращают **200, status=completed** только после успешного сохранения и пересчёта. Это осознанное упрощение раннего плана с очередью/202 для небольшого набора.

Параметры рейтинга: `sort_by=id|email|balance|totalReplenished|score`, `sort_order=asc|desc`, `risk_level`, `search`, `page`, `page_size`. Сортировка выполняется до пагинации; неизвестный score всегда в конце. Данные сортируются в памяти опубликованного расчёта: для большого production-набора понадобится индексируемая проекция в БД.

## Prometheus

`/metrics` доступен с сессией или отдельным `METRICS_TOKEN`. Токен сборщика не даёт доступ к клиентским API.

Пример scrape-конфигурации, если Prometheus в той же Docker-сети:

```yaml
scrape_configs:
  - job_name: retention
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials_file: /run/secrets/retention_metrics_token
    static_configs:
      - targets: [backend:8000]
```

Поместите значение токена в указанный файл сборщика. Сам Prometheus в Compose не включён. Проверка с хоста после задания токена в окружении PowerShell:

```powershell
Invoke-WebRequest http://localhost:8080/metrics -Headers @{ Authorization = "Bearer $env:METRICS_TOKEN" }
```

Есть количества всех уровней, сценарная сумма EUR, известные обязательства, дефицит, неизвестные услуги, средний индекс известных клиентов, версия и время расчёта. Если оценённых клиентов нет, средний score — NaN, число оценённых — 0. Персональные данные не используются в метках.

## Модель, архитектура и расширение

Смотрите `docs/model.md`, `docs/architecture.md`, `docs/demo.md`. Стартовые веса: выключенное автопродление 25, дефицит 30, ожидание оплаты 30, срочность 15. Средний риск от 30, высокий от 60. Score не является обученной вероятностью оттока.

Деньги исходника хранятся в евроцентах; 100 единиц = 1 EUR. Доступный баланс — основной плюс бонусы только при unlocked, без withdrawBalance. Баланс распределяется между услугами один раз по времени платежа и ID. Периоды оплаты рассчитываются календарно; суммы транзакций не заменяют цену услуги.

## Проверки и ограничения

В среде разработки проверены:

- backend: 43 pytest-проверки на SQLite, включая денежный пример 63 EUR, общий баланс/бонусы, календарь, реальные DTO, сортировки, сессии/CSRF, повторный импорт, сценарии «Что если?», историю статусов, очередь контактов, рестарт, метрики и SSE;
- оригинальный генератор: 3 unittest-проверки, совпадение JSON и SQL;
- production-сборка React/TypeScript;
- генерация OpenAPI и компиляция схемы для PostgreSQL.

На сервере проверены сборки Docker, миграция PostgreSQL, запуск Compose и ответы основных API. Перед защитой проверьте пользовательский сценарий в браузере с актуальными данными.

Ограничения v0.4: один backend worker; расчёты и опубликованный JSON рассчитаны на небольшой набор; история версий пока не очищается автоматически; нет OIDC, ML и пользовательского управления учётными записями. При падении периодического расчёта остаётся предыдущая опубликованная версия, а число ошибок доступно в summary/metrics. Внешний веб-шрифт необязателен: при недоступности используется системный.

### Тесты через Compose

После сборки:

```bash
docker compose run --rm backend python -m pytest -q
docker compose run --rm backend python -m unittest discover -s /app/data/original -p test_generate.py -v
```

API-тесты используют отдельные временные SQLite-БД, не рабочую БД приложения. Для PostgreSQL-интеграции есть `scripts/check_postgres.py`; запускайте только против отдельной пустой тестовой БД (см. docs/architecture.md).

### Локальная разработка без Docker

Python 3.12, Node.js 22+ и npm. SQLite используется только для локального запуска и тестов; Compose использует PostgreSQL.

```bash
python -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cd frontend
npm ci
cd ..
python scripts/init_env.py
npm run dev
```

На Windows вместо `.venv/bin/python` используйте `.venv\Scripts\python.exe`, а вместо `python` при необходимости `py`. `scripts/dev.mjs` запускает миграции, backend на 8000 и Vite на 4173. Откройте http://localhost:4173 . В `.env` для локальной SQLite не задавайте DATABASE_URL; launcher создаст `.runtime/aeza.db`.

Сборка frontend: `cd frontend && npm run build`. Тесты backend: из `backend` запустите `../.venv/bin/python -m pytest -q` (на Windows путь к python.exe соответственно).

## Остановка

```bash
docker compose stop
docker compose start
```

Настройки, пользователи и данные находятся в volume PostgreSQL. Обычная остановка не удаляет volume. Файл `001_schema.down.sql` разрушителен и не используется приложением при запуске или остановке.
